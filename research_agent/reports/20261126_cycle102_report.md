# サイクル102 結果レポート (2026-11-26)

## 概要: サイクル101の未解決の問い(「本来バイアスのない比較で高い一致率を示すか」)を検証 — 予測は外れたが、より興味深い「引き分け対決定」の非対称性を発見

`GENERATE_HYPOTHESES -> HUMAN_APPROVAL -> RUN_EXPERIMENTS -> ANALYZE_RESULTS -> WRITE_REPORT`

## 背景: サイクル101が明示的に残した未検証の問い

サイクル101の`reflections.md`は、スワップ&一致確認緩和策(`soumik2026`/`xu2026`)
について次のように明示的に指摘していました:「この結果は緩和策が**既に既知の

信号が明確に優勢であるはずの比較で、緩和策が正しく**高い**一致率を示すか(偽陰性を
出さないか)は、まだ未検証である」。本サイクルはこの問いに直接取り組みました。

## RUN_EXPERIMENTS: 実装前に既存コードを読み、仮説記述の誤りを発見・修正

環境チェック: `DEEPGRAM_API_KEY`/`GOOGLE_API_KEY`/`OPENAI_API_KEY`はいずれも
設定済み、`ffmpeg`も利用可能、Gemini REST(`generativelanguage.googleapis.com`)
への到達性も200で確認。本仮説はGeminiのjudge呼び出しのみを必要とし、Deepgram/
OpenAIへの到達性は不要なため、現在ブロック中の他4件(Deepgram WebSocketアップ
グレード障害、OpenAI CONNECT拒否、rm-2278様の視聴時間待ち)とは独立して実行
可能でした。

新規スクリプト`judge_pairwise_swap_agreement_unbiased_check.py`を実装する前に、
対象データを生成した`soft_anchor_generalization_replay.py`を実際に読んだところ、
**本仮説自身の`required_changes`の想定が誤っていた**ことが判明しました:
記述では「repeatインデックス1を使い、バッチをまたいで連結した全文」を使う予定
でしたが、実際にはその生成スクリプトの99行目`translation_full = repeats[0][-1]`
により、既存の60点/100点というスコアは**repeat 0の最後のバッチのみ**(全文では
ない)をスパン全体のソーステキストと比較して判定されたものでした。既存スコアと
公平に対応する比較にするため、スクリプトは`condition_repeats[condition][0][-1]`
(repeat 0の最後のバッチのみ)を使うように実装しました。これはPLAYBOOK.mdが
繰り返し指摘している「イベントフィールドの構造を仮定せず、実際のコードを読んで
確認する」という教訓の、また別の実例です。

スワップ&一致確認を**最初から**組み込んだ設計(後から別スクリプトで再分析する
のではなく)で、20回の新規gemini-3.1-flash-lite判定呼び出し(10回はA枠に
`soft_anchor_replay`、10回はB枠に入れ替え)を実行し、`$0.01`をログしました。

## ANALYZE_RESULTS: 予測は外れたが、重要な非対称性を発見

**予測**: 40点という明確な差であれば、一致率は高いはず(例: 80%以上)。

**実際の結果**: `agreement_rate = 0.2`(10ペア中2ペアのみ一致) — 予測を大きく
下回りました。しかし、各回答の推論テキストを詳しく読むと、より興味深い構造が
見えてきました:

- **一度も逆転していない**: 20行すべてのうち、`baseline_replay`(劣る側)を
  内容面で支持した判定は**ゼロ件**でした(素朴な集計でも`worse_condition_win_rate
  = 0.0`)。
- **スロットBでは完全に決定的**: `soft_anchor_replay`がB枠に入った10回は、
  **全10回**が明確に「B」を選び、理由付けでも一貫して「我々は」(we)という
  主語の保持を正しく指摘していました。
- **スロットAでは「引き分け」に逃げる**: `soft_anchor_replay`がA枠に入った
  10回のうち、決定的に「A」を選んだのはわずか2回。残りの8回は、同じ内容的な
  差が利用可能であるにもかかわらず「引き分け」と判定しました。
- `verdict_slot_a_rate = 0.1`(A枠を明確に選んだのはわずか10%)で、これも
  この非対称性と一致します。

**これはサイクル100/101の現象とは異なる、より軽微な失敗モード**です。サイクル
100は「内容に関係なく常にスロットBを選ぶ」という完全な決定論的反転でしたが、
今回は「判定の極性が反転することは一度もないが、良い候補がA枠にあるときだけ
『引き分け』で逃げる」という非対称性です。現在のスワップ&一致確認の二値的な
指標(`content_preferred`の完全一致のみを「一致」とみなす)は、この2つを区別
できません — 「逆転した判定」(緩和策が本来検出すべき本当の危険)と、「引き分け
対決定の非対称性」(今回のケース、より軽微)を同じ「不一致」として扱ってしまい、
一致率を実態より低く見せています。

**結論**: サイクル101の未検証だった問い(「本来偏りのない比較で高い一致率を
示すか」)に対する直接の答えは「いいえ、現状の二値指標では高い一致率は出ない」
ですが、それは判定内容が実際に間違っているからではなく、指標自体が「引き分け」
を独立した不一致カテゴリとして扱っているためです。「引き分け対決定」をより
穏やかな不一致として扱う改良版の指標であれば、より高い実効一致率を示す可能性が
高いですが、これは今回事後的に指標を作り変えることは避け、将来の仮説として
明示的に残しました。
